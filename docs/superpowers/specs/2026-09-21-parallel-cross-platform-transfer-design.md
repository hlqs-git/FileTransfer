# 并行跨平台文件传输设计

## 背景与目标

当前项目使用 Bash 脚本串行上传和下载分片，只能直接运行在 Linux/Unix shell 环境中。目标是提供一个统一的 Python 3 命令行客户端，在 Windows 和 Linux 上使用相同命令，并通过并发传输提升大文件上传和下载速度。

成功标准：

- Windows 和 Linux 安装 Python 3 后即可运行，不需要安装第三方包。
- 上传和下载默认使用 4 个工作线程，并允许在 1 到 16 之间配置。
- 保留分片 MD5 与完整文件 MD5 校验。
- 兼容当前项目已经生成的 `manifest.txt`。
- 网络错误和临时 HTTP 错误能够自动重试。
- 下载可以复用已经完整并校验通过的分片。
- 上传失败时不能发布不完整的最终清单。

## 范围

本次新增统一入口 `file-transfer.py`：

```text
python file-transfer.py push <file> [options]
python file-transfer.py pull [manifest] [options]
```

现有 `file-push.sh` 和 `file-pull.sh` 暂时保留，用于兼容已有 Linux 使用方式，但 README 将 Python CLI 标记为推荐入口。本次不修改 Cloudflare Worker 服务端，也不实现单个 HTTP 请求内部的可续传上传。

## 命令行与配置

### 通用参数

- `--auth TOKEN`：上传或下载认证 Token。
- `--workers N`：并发工作线程数，默认 4，允许范围 1 到 16。
- `--retries N`：每个分片的最大尝试次数，默认 3。

认证支持命令参数和环境变量。命令参数优先，环境变量作为默认值：

- `FILE_TRANSFER_AUTH`
- `FILE_TRANSFER_URL`

Token 不写入日志或清单。

### push 参数

- `--url URL`：上传服务地址；未传时读取 `FILE_TRANSFER_URL`。
- `--manifest PATH`：输出清单路径，默认 `manifest.txt`。
- `--chunk-size SIZE`：分片大小，默认 `90M`。
- `--expires SECONDS`：服务端有效期，默认 3600 秒；传 0 时不发送 `X-Expiration-Seconds`，使用服务端的一次性下载模式。

### pull 参数

- `manifest`：清单路径，默认 `manifest.txt`。
- `--output PATH`：最终输出文件路径；默认使用清单中的文件名并写入当前目录。

## 服务端约束

目标服务基于 `hlqs-git/bashupload-r2`。经检查，该 fork 没有配置 Cloudflare Worker rate-limit binding，上传处理路径也没有每分钟 10 次的应用层限流，因此默认 4 路并发不会触碰该限制。

服务端不带 `X-Expiration-Seconds` 的对象采用一次性下载模式，开始响应后会安排删除。带有效期的对象在过期前允许重复下载。因此客户端默认发送 3600 秒有效期，以保证下载校验失败或网络中断后能够重试。用户仍可显式选择一次性模式。

## 架构

采用单文件 Python CLI，内部按职责划分为小型函数和数据类：

- 参数与配置解析：合并命令参数、环境变量和默认值。
- 清单模型：解析、校验和序列化新旧清单。
- 分片规划：根据文件大小和分片大小生成编号、偏移和长度。
- HTTP 传输：使用 Python 标准库创建请求、处理认证、状态码和重试。
- 并发协调：使用 `concurrent.futures.ThreadPoolExecutor` 调度分片任务。
- 完整性校验：计算分片与完整文件 MD5。
- 状态与落盘：管理下载状态目录、临时文件和原子替换。

不使用 `requests`、`aiohttp` 等第三方依赖。线程适合以网络等待为主的传输任务，并且比为该项目引入异步框架更容易部署和维护。

## 上传数据流

1. 校验源文件、URL、认证信息和参数。
2. 流式计算完整文件 MD5，并根据文件大小建立逻辑分片计划。
3. 每个工作线程独立打开源文件，跳到分片偏移，只读取该分片长度。
4. 工作线程计算分片 MD5，并以 PUT 请求流式上传该范围；请求设置明确的 `Content-Length`，避免把整个分片读入内存。
5. 默认发送 `X-Expiration-Seconds: 3600`；认证通过 `Authorization` 请求头发送。
6. 从响应正文中提取服务端返回的下载 URL，并将结果写入内存中的对应分片槽位。
7. 所有分片成功后，按照分片编号排序，通过同目录临时文件和 `os.replace` 原子生成最终清单。
8. 任一分片最终失败时取消尚未开始的任务，不生成或覆盖最终清单。已上传的孤立对象由服务端过期清理。

上传不提供跨进程断点续传，因为服务端 URL 有时效性，旧任务留下的 URL 不能可靠复用。

## 清单格式与兼容性

保留现有核心字段与分片行：

```text
HASH:<完整文件 MD5>
NAME:<文件名>
VERSION:2
SIZE:<文件字节数>
CHUNK_SIZE:<分片字节数>
EXPIRES:<有效期秒数>
<分片 MD5>|<下载 URL>
```

规则：

- `HASH` 和 `NAME` 必须存在且只能出现一次。
- `NAME` 只保存 basename，不能包含目录穿越。
- 元数据行可以被旧 Bash 下载脚本忽略。
- 分片行在清单中始终按原始文件顺序排列，与并发完成顺序无关。
- Python 客户端接受没有 `VERSION`、`SIZE`、`CHUNK_SIZE` 和 `EXPIRES` 的旧清单。
- 未识别的元数据键保留为可忽略扩展，避免未来版本无法读取。

## 下载数据流与恢复

1. 解析并验证清单，确定安全的目标文件名或使用 `--output`。
2. 使用清单内容摘要生成独立状态目录：`.file-transfer/<安全文件名>-<清单指纹>/`。
3. 每个分片对应固定编号的临时文件。启动时检查已有分片，MD5 正确则跳过；错误或不完整文件先删除。
4. 缺失分片通过线程池并发下载到同目录临时文件，完成后计算 MD5；只有校验通过才原子替换为正式分片文件。
5. 所有分片验证通过后，按编号流式合并到目标路径旁的临时输出文件。
6. 校验完整文件 MD5。成功后使用 `os.replace` 原子替换最终文件，并删除状态目录；失败时保留分片以便诊断和再次运行。

下载恢复是客户端级别的“完整分片复用”，不依赖 HTTP Range。正在下载但未完成的半个分片不会被复用。旧的一次性下载链接一旦被服务端消费，客户端无法恢复该远端对象，会明确报告 404。

## 重试与错误处理

每个分片默认最多尝试 3 次。第 1、2 次失败后分别等待约 1 秒和 2 秒；如果服务端返回合法的 `Retry-After`，优先遵守该值并设置合理等待上限。

可重试情况：

- 连接建立失败、连接重置、读取超时等临时网络错误。
- HTTP 408、429 和 5xx。
- 下载完成后分片 MD5 不匹配。

不可重试情况：

- HTTP 401、403：认证或权限错误。
- HTTP 404：对象不存在或已经过期/被消费。
- 清单格式错误、参数错误、输出路径不可写。

用户按 Ctrl+C 时取消尚未开始的任务。下载端保留已经校验的分片；上传端不发布清单。日志按分片编号输出简洁进度，异常信息不包含 Token。

## 安全与文件系统行为

- 清单中的 `NAME` 始终通过 basename 归一化，并拒绝空值、`.` 和 `..`。
- 所有输出路径使用 `pathlib.Path`，避免依赖平台路径分隔符。
- 临时清单和临时输出与目标文件位于同一目录，以保证 `os.replace` 的原子性。
- 下载不直接写最终文件，失败不会留下看似成功的输出。
- HTTP 重定向遵循标准库行为，但认证头只用于用户指定的请求；实现和测试需防止跨主机重定向泄露认证信息。
- 日志只显示服务地址、分片编号、状态和错误类别，不显示认证值。

## 测试策略

测试使用 `unittest` 和本地 `ThreadingHTTPServer`，不访问真实 R2，也不要求外部依赖。

覆盖范围：

- 参数校验、环境变量回退和命令参数优先级。
- 分片大小解析、分片边界和空文件。
- 新版清单往返、旧清单解析、路径穿越防护和分片顺序。
- 本地服务端观测到多个同时活动的上传/下载请求，证明并发实际生效。
- 分片乱序完成时生成的清单仍保持正确顺序。
- 临时网络错误、408、429、5xx 和校验失败的重试。
- 401、403、404 不进行无意义重试。
- 上传失败不生成或覆盖最终清单。
- 下载跳过已有且 MD5 正确的分片，重新获取损坏分片。
- 合并后的最终 MD5 与原文件一致，成功后清理状态目录。
- 文件名包含空格、非 ASCII 字符和前导连字符。
- Windows 与 POSIX 风格的旧清单路径都只恢复安全文件名。

## 文档与迁移

README 将增加 Windows 和 Linux 示例、参数表、环境变量示例、有效期语义以及旧清单兼容说明。现有 Bash 脚本不会在本次删除；用户可以逐步迁移到统一 Python CLI。

典型用法：

```text
python file-transfer.py push archive.tar.gz --url https://r2.example.com --auth TOKEN
python file-transfer.py pull manifest.txt --auth TOKEN
python file-transfer.py push archive.tar.gz --workers 8 --expires 7200
```
