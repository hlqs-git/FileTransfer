# Shell 传输可靠性设计

## 目标与约束

为 CentOS 7/8、Rocky Linux 和 Ubuntu 保留无需 Python 的传输入口。基线为 Bash 4.2、curl 7.29 及常见 GNU 工具；不修改 `file-transfer.py`。继续支持 `file-push.sh FILE` 和 `file-pull.sh`。

## 方案比较与决定

已确认采用现有双脚本渐进增强方案：先保证失败处理、重试、校验和下载恢复。完整并发调度增加进程管理复杂度，本轮不实现；POSIX/BusyBox 专项适配也不在本轮范围。

## 行为

- 新环境变量沿用 `FILE_TRANSFER_URL`、`FILE_TRANSFER_AUTH`，上传兼容旧 `url`、`auth`；支持清单路径、分片大小、额外重试次数及链接有效期配置。参数覆盖环境变量。
- 上传分片放在私有临时目录，检查 HTTP 结果和唯一下载链接。全部完成后在清单所在文件系统原子替换清单；失败保留已有清单。上传不提供跨命令续传。
- 下载先验证整个清单，兼容旧格式及 Python 元数据、CRLF 和绝对路径文件名。按清单顺序恢复，不混入旧分片。
- 下载状态按清单隔离，复用前校验完整分片，未完成分片重新下载；不做 HTTP 字节级续传。独立锁防止同一状态被同时修改。
- 在目标目录组装临时文件，最终 MD5 正确后才原子替换目标。失败保留已有目标及可恢复分片。
- 默认验证 TLS，不修改系统网络参数，不内置认证信息。超时及有限重试使用旧版 curl 支持的选项。日志写 stderr，成功路径写 stdout。
- 默认链接有效期为 3600 秒；有效期为 0 时说明一次性链接对重试和恢复的限制。

## 验证

增加离线 Shell 回归用例，覆盖失败保护、下载恢复、损坏分片、清单兼容、文件名与参数处理；运行原 Python 测试以确认无回归。当前主机是 Windows，使用已找到的 Git Bash 运行脚本，并通过本机 HTTP 服务验证两种客户端清单互通。未安装 Linux 发行版，最终说明尚未在目标发行版的真实旧版运行时上验证。
